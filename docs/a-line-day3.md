# A 线冲刺第 3 天：本队赛程管理与取消比赛

更新日期：2026-10-04。接续 [第二天交接说明](a-line-day2.md)，本日完成队长管理入口、管理列表、编辑跳转、取消事务、二次确认与取消项只读。沿用此前安排，仅进行本地实现与验证，部署和真机验收由用户处理。

## 本地已实现

- 首页队长区新增“管理本队赛程”，路由 `/pages/schedule-list/index`。游客、部员和运营者不显示队长入口；直达列表同样有身份守卫。
- 列表调用 `getMyMatches`，本队未归档项按更新时间倒序排列，保留已取消项。展示项目、队伍、对手、时间、地点和状态，覆盖加载、空态、失败重试、下拉刷新及返回刷新；过期响应不会覆盖新的列表。
- 点击列表项携带 matchId 进入表单，继续使用 `getMatchForEdit` 原始数据回填。取消项只读；保存后可返回列表或重新加载继续编辑。返回已有列表使用 navigateBack，避免反复编辑累积页面层级。
- `cancelMatch({ matchId, version })` 事务内重读用户、启用队伍与比赛，校验本队归属、version 和状态；允许 pending/confirmed/help/tbd/dutyCancelled，拒绝 settle、已归档或到达 endTime 的比赛。按现有取消契约，已开赛但尚未结束的比赛仍可取消。
- 首次取消将状态设为 cancelled、version +1、更新 updatedAt，清空全部跟场快照；不递增 dutyRevision，不删除 DutyRecord。取消先识别已取消状态再校验 version，因此并发取消及旧版本重试都只递增一次。
- 取消清空旧编辑幂等缓存，防止旧编辑响应把已取消比赛显示成原状态；保留 createRequestId，旧新建重试不会产生第二场比赛。
- 表单明确二次确认，提示无法恢复、跟场确认清空及草稿不提交。取消成功回到已保存的只读详情，即使随后详情刷新失败，也不会显示未保存草稿为已保存数据。
- 取消请求进行中或结果不确定时锁住编辑/保存/刷新按钮；弱网重试保留原 matchId/version，不再次弹确认。明确的 404/409 锁住操作，要求加载最新赛程，再重新确认。
