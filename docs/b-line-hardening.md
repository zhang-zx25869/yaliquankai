# B 线代码收尾：事务、页面与回归

更新日期：2026-10-07。基于 `399d424`，完成此前核对出的 B 线代码缺口。未部署云函数，未进行真实云数据库或真机验收。

## 已完成的代码工作

- **原子表态**：确认、没空、救场、取消在同一事务中写 Match 快照/状态和本人 DutyRecord。留痕写入失败时整体回滚，确认与救场竞争只留下一个跟场人。事务重读身份、权限、比赛状态、时间、赛程基准，拒绝开赛/归档/取消后的操作。
- **稳定重试**：新客户端四种表态均携带 `requestId`，不确定结果保留原请求，禁止同时发起其他动作。本人记录缓存最近一次请求与结果，落库后响应丢失可重试；新记录用确定性 ID，旧随机 ID 原地更新，保留一人一场 upsert 语义。
- **旧页面保护**：B 线 DTO 增加不透明 `dutyToken`，客户端原样提交。赛程或跟场快照变化后拒绝旧操作，避免从旧页面确认已改时间/地点的比赛；旧意图在后续操作后重试也不能覆盖新状态。同一已提交请求优先返回原结果，不重新写入。
- **聚合竞争保护**：内部 `dutyVersion` 只由 B 线表态递增，不改变 A 线 `version/dutyRevision`。人数聚合在事务外读取，事务验证期间未发生其他 B 线表态；不匹配时重新读取并有限重试。团队成员数等跨集合聚合仍保留读时重算兜底，不宣称具备全库快照一致性。
- **读取与分享**：重算后重读最新 Match，避免 DTO 状态新、跟场人旧；我的跟场和历史统计按 100 条分页；北京时间格式化；校验 action、matchId、requestId、重复身份和重复留痕；异常与不存在分开处理；求助卡片守卫角色、队伍、开赛/终态并编码路径。跨队救场者可接单，但不获本队求助卡片权限。
- **页面请求**：respond/rescue 共用 `utils/duty-page.js`，清除原页面内的 mock 分支。三页支持加载失败独立重试、下拉刷新，隐藏/卸载/身份变化和旧请求失效；旧刷新不关闭新提示，操作中的隐藏/返回不遗留 busy 状态。
- **按钮与分享**：二次确认前即锁定重复点击；关闭页面后不继续提交确认弹窗；同步分享仅使用有效预加载数据，分享未就绪时禁用，支持独立重试，刷新/操作/离开/身份变化/到期开赛均使旧卡片不可用。
- **我的跟场**：接通卡片展开事件，补齐运营者取消自己跟场的按钮；操作失败可重试；取消变红后本队经理人进入 respond，跨队救场者进入 rescue，避免跳转到无权限页面。
